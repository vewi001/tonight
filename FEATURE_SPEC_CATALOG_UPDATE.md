# Отдельное обновление каталога Tonight

## Потребители и границы

Автор готовит пакет; основной компьютер добровольно получает его с публичного
GitHub. Телефон читает обычные карточки, но не управляет установкой. TMDB-токен
автора не нужен получателю и никогда не входит в пакет. Существующие app-update
пакеты 1.6.5 не меняются. Реализация и публичная end-to-end проверка завершены
10.10.2026; доказательства — CATALOG_RELEASE_CHECKLIST.md и журнал прогресса.

## Пакет, формат 1

- ZIP `Tonight-catalog-X.Y.Z.zip`, самостоятельная числовая версия каталога.
- Версии — канонические X.Y.Z без префикса v/ведущих нулей, до 32 символов;
  совместимость сравнивается численно, не лексикографически.
- `tonight-catalog.json`: product=Tonight, kind=catalog, format=1, version,
  min_app_version, created_at (UTC), movie_count, files (точные имена, размер,
  SHA-256 каждого файла содержимого).
- `movies.json`: только публичная проекция movies; не пользовательская SQLite.
  При получении не исполняются SQL, миграции или триггеры из пакета.
- Опционально `posters/<movie-id>.<jpg|jpeg|png|webp>` и backdrops с тем же
  правилом. Никаких EXE, .env, пользователей, истории, абсолютных локальных
  путей, SQL-файлов, трейлер-видео или постороннего содержимого.
- Не более 10 000 файлов и 500 МиБ распакованного содержимого; до 20 000
  карточек, movies.json до 32 МиБ. Небезопасные Windows-пути, неоднозначные
  имена, case-insensitive дубликаты и ZIP-ссылки отклоняются.
- Точная whitelist полей карточки задаётся в backend/catalog_package.py.
  Неизвестные поля не переносить молча. trailer_key — только YouTube ID;
  poster_path/backdrop_path и произвольные URL в формате отсутствуют.
- Повторяющиеся ключи JSON на любой вложенности запрещены: один пакет не
  должен получать разные значения версии/идентичности у разных читателей.

## Подготовка

CLI scripts/build_catalog_package.py требует источник, версию каталога,
минимальную версию приложения и новый выходной ZIP. Существующий ZIP не
перезаписывается. Источник открывается read-only, персональные таблицы не
читаются и не экспортируются. Без флагов пакет содержит только метаданные.
Для включения медиа требуются --include-media и --media-rights-reviewed:
это подтверждение ответственности автора, не автоматическое предоставление
прав. Копируются только распознаваемые файлы соответствующих карточек.
Состав и порядок стабильны; created_at позволяет фиксированное UTC-время
для воспроизводимой проверки. Выход публикуется атомарно после проверки.

## Получение и совместимость

Отдельные стабильные GitHub Releases catalog-vX.Y.Z публикуются НЕ как Latest
приложения. Поиск каталога использует releases list, а app-update продолжает
использовать Latest. Ограничить частоту и объём запросов, учитывать пагинацию.
Discovery выбирает последний новый candidate, не путая номер каталога с EXE.
Совместимость устанавливается по проверенному ZIP, не по номеру релиза. Если
новейший пакет требует новый Tonight, предложить обновить приложение;
автоматический поиск/загрузка старых пакетов в обход этого предложения не выполняется.
Для общего ZIP обязательны размер и digest GitHub; переиспользовать проверки
хостов, HTTPS-редиректов и частичной загрузки из app-update, но не EXE-манифест.
Каталог с min_app_version выше установленной не применять: предложить
обновить приложение. Локальное отсутствие версии показывать как «Версия
каталога ещё не указана», не придумывать дату предыдущего обновления.
read_catalog_package(..., app_version=...) проверяет совместимость; автор
при сборке может читать пакет без app_version. Установщик обязан
передавать реальную версию приложения, а не оставлять эту проверку выключенной.

## Слияние и исправления (утверждено пользователем 09.10.2026)

Известное поведение 1.6.5 сохраняет заполненные поля и существующие медиа.
Пользователь подтвердил сохранение личных изменений: хранить baseline
управляемых полей и исправлять лишь совпадающие с baseline;
отличающиеся значения считать локальными изменениями. Для старой базы без
baseline заполненные поля не перезаписывать. Исправления не удаляют фильмы
и не меняют локальные идентификаторы.

Поле без baseline становится управляемым только при заполнении отсутствующего
значения (NULL); ранее заполненные поля старой базы не присваивать пакету даже
если они случайно совпали. Пустая строка считается заполненным значением.
Отсутствующее поле или NULL в новом пакете — отсутствие сведений, не команда
очистки: сохранить значение и прежний baseline. При личном отличии сохранить
само отличие, но для непустого поля запомнить новый официальный baseline.
Чистый plan_field_updates работает с нормализованными JSON-значениями уже
проверенной идентичности фильма. Он не меняет id/tmdb_id и не пишет в базу;
future consumer обязан атомарно сохранить изменения и baseline вместе.

Новые записи добавлять по стабильной идентичности: tmdb_id, затем совместимый
id/название+год. При совпадении tmdb_id сохранять локальный id. Конфликт id
для разных фильмов отклонять до изменения базы, не перепривязывать историю.
Не применять INSERT OR REPLACE к пользовательским movies. Не удалять
фильмы, историю или личные строки; проверить все ссылки и уникальные индексы.

Чистый resolve_catalog_ids выполняет preflight всего проверенного пакета без
записи в базу. Приоритет tmdb_id; затем совместимый case-insensitive id;
затем original_title (после trim, иначе title) + год. Два разных известных
tmdb_id не объединять даже при одинаковых названиях/годе. Неоднозначность,
занятый чужим фильмом id и несколько карточек на один локальный фильм
отклонять целиком. Существующие дубли автоматически не удалять. Consumer
обязан использовать согласованный снимок базы и повторную проверку под
блокировкой установки; сопоставление также нужно применить к именам медиа.

## Установка, ошибки, интерфейс

acquire_update_lease(root) создаёт/открывает фиксированный .tonight-update.lock
в существующей папке установки, проверяет ссылки и получает неблокирующую
межпроцессную OS-блокировку. UpdateBusyError означает уже выполняющийся job;
UpdateGuardError — безопасную ошибку пути/доступа. Lease.close идемпотентен,
может вызываться другим worker thread; после смерти процесса OS снимает lock.
Файл lock остаётся пустым/служебным и сам по себе не означает активный job.
App manager держит lease от reserve_download через ready/installing до выхода
процесса; fail освобождает. Будущий catalog manager пользуется тем же lease.
Внешний app installer получает lease после ожидания старого процесса и
удерживает до завершения restart/rollback. Ручные update/rollback также
используют guarded wrappers; сам apply_release — низкоуровневая операция,
её caller обязан держать lease. .tonight-update.lock защищён от архива,
копирования программного rollback snapshot и восстановления поверх lock.

Внутренний merge_catalog_movies(db, movies) требует открытую транзакцию
и включённые foreign_keys. Caller начинает BEGIN IMMEDIATE под общей
блокировкой установки. Helper валидирует JSON, сопоставляет весь пакет,
нормализует SQLite-списки, применяет INSERT/UPDATE и baseline под SAVEPOINT.
Ошибка откатывает весь срез, но не чужие изменения внешней транзакции;
успешный возврат НЕ коммитит внешнюю транзакцию и НЕ означает успех установки.
Новая таблица catalog_field_baselines хранит только управляемые публичные
поля по локальному movie_id; личные таблицы и app_meta не меняются.
tmdb_id можно добавить отсутствующему после однозначного сопоставления;
известный tmdb_id и локальный id не заменяются. Helper не пишет медиа,
версию каталога или дату: это атомарные обязанности будущего installer.

Перед записью: полная валидация, проверка локальных symlink/junction и backup.
Слияние базы транзакционное; медиа предварительно staged, с восстановлением
при сбое. Между установкой каталога и приложения — единая блокировка.
Не допускать частичного успеха, гонок и перезаписывания личных данных новой
копией базы при активных пользовательских действиях. Проверить сценарий
отключения питания/следующего запуска до выбора способа восстановления.

GET /api/catalog; POST /api/catalog/updates/check, /install и /recover —
аддитивные маршруты. Управление localhost-only, с теми же Origin/Host и
action-header ограничениями, что app-update. Статусы idle/checking/current/
available/downloading/installing/done/error/recovery_error; версия и дата обновляются только
после завершения операции. Публичный ответ без путей, токенов и traceback.

Экран «Каталог»: фильмы, количество карточек с локальным существующим
постером и корректной ссылкой на трейлер, версия, последнее успешное обновление.
Наличие ссылки не доказывает доступность видео. Отдельные действия обновления
приложения и каталога. Ошибка сети не блокирует локальный выбор фильма.

Read-only get_catalog_summary(db, data_dir): movie_count, local_poster_count,
trailer_link_count, poster_and_trailer_count, catalog_version,
last_successful_update. Постер — непустой обычный файл допустимого расширения
с именем локального id, не generic artwork, не symlink/junction. Ошибка чтения
папки означает нулевой доступный кэш, но не мешает посчитать фильмы.
Это проверка наличия файла, не полного декодирования изображения.
Ссылка — только корректный YouTube key; доступность видео не проверяется.
Версия/дата берутся из app_meta catalog_version/catalog_updated_at, только
после будущего commit installer. Для старой базы обе null; версию приложения
не подставлять и дату по изменению файла не выдумывать. Секреты/пути не возвращать.

select_catalog_update(releases, current_catalog_version) — чистый выбор из
списка публичных релизов; не /releases/latest. Только catalog-vX.Y.Z, без
draft/prerelease; максимальная новая численная версия с одним ожидаемым
Tonight-catalog-X.Y.Z.zip, корректными size/digest и точным URL нашего repo/tag.
Отсутствие catalog asset — не готовый релиз, пропустить. Конфликт одинаковых
версий или некорректный выбранный asset — безопасная ошибка, не fallback
на подозрительный пакет. current null допускает первую установку. Это только
выбор candidate: minimum app version пока неизвестна и обязательно проверяется
по скачанному манифесту до записи, candidate не означает совместимость.

download_catalog(update, destination, app_version, client=None, progress=None)
скачивает candidate в эксклюзивный временный файл, проверяет точный исходный
repo/tag URL, разрешённые HTTPS redirects, size/SHA-256, весь ZIP и manifest,
версию каталога и min_app_version. Только затем публикует полный ZIP без
перезаписи существующего файла. Не устанавливает и не извлекает пакет.
Пути destination/parents не могут быть ссылками; временный файл удаляется
при любой ошибке. Production HTTP client не наследует env proxy/auth/TMDB.

fetch_catalog_update читает только фиксированный GitHub releases endpoint,
per_page=100, максимум 10 последовательных страниц. Завершение по короткой
странице; исчерпание лимита, неправильный JSON, HTTP/network/rate limit —
безопасная ошибка, не «обновлений нет». Никакой token/auth/env proxy.
Будущий manager должен добавить cache/throttling; HTTP helper не устанавливает.

## Готовность всей функции

UI: раздел «Каталог» в основной навигации только localhost. Сводка показывает
movie_count, local_poster_count, trailer_link_count, poster_and_trailer_count,
отдельную catalog_version и дату successful update. Для legacy: «Пакет ещё не
установлен» и «Обновлений пакетом ещё не было», без выдуманной версии/даты.
Подпись поясняет, что доступность YouTube видео не проверена. Отдельные панели
обновления каталога и приложения; catalog check/install/recover используют
защищённые API, не URL/путь пользователя. Busy запрещает повторный клик;
статус polling 1.5 с во время job, 30 с на открытом экране, без сетевых
GitHub-запросов на каждый poll. Вне экрана polling продолжается лишь для active
job. Ошибка status не превращается в success/current. Поля/ошибки экранируются;
обновление панели не перерисовывает текущий вечер или всю страницу.

HTTP интеграция (additive): GET /api/catalog возвращает {summary, update};
summary — get_catalog_summary, update — status manager. GET только основной
компьютер. POST /api/catalog/updates/check, /install, /recover требуют loopback
client, localhost Host, X-Tonight-Update: 1 и совпадение Origin, если он есть.
Никаких URL/путей/пакетов из request. install резервирует проверенный offer,
возвращает 202 и запускает tracked worker; конфликт 409 с безопасным detail.
check/recover возвращают 200 с состоянием (сетевая ошибка — phase error).
Startup вызывает recover ДО initialize/bootstrap/seed; при recovery_error
локальный вечер доступен, install запрещён. Shutdown ожидает catalog worker,
чтобы не освобождать lock при живом потоке. Нового auto download нет.
Страховочные DB копии хранятся в data/backups, чтобы штатное удаление личных
данных удаляло и их. Create/restore/import backup и privacy delete берут тот же
update lease, выполняют recovery перед изменениями; при busy/ошибке recovery
409, без изменений. Restore держит lease до initialize/bootstrap/seed.

CatalogUpdateManager(root, app_version, database=None) — внутренний потокобезопасный
координатор. status возвращает только current_version, available_version, phase,
download_bytes, total_bytes, message; никаких путей/исключений/секретов. Фазы idle,
checking, current, available, downloading, installing, done, error, recovery_error.
check(force=False) читает текущую catalog_version из БД, кеширует результат 6 часов;
ручной force ограничен одним сетевым запросом в минуту. Ошибка проверки очищает
старое предложение; active job не допускает новой проверки/резервирования.
reserve_download() получает общий app/catalog lease, возвращает candidate.
run_reserved(candidate) допускает ровно одного worker этой reservation, скачивает
в отдельную папку, передаёт lease установщику и освобождает только после полного
завершения/ошибки. Скачанный ZIP не считается успехом; done только после install
и cleanup recovery. Startup recover() должен вызываться до bootstrap/seed/UI;
ошибка recovery запрещает новый catalog job, но не обычный локальный вечер.
Повтор recover разрешён; сырые исключения worker никогда не попадают в status.

install_catalog(root, archive, update, app_version, database=None, lease=None)
работает только с инициализированной локальной SQLite внутри root и доверенным
candidate из GitHub discovery. Берёт общий lease (либо проверяет переданный),
восстанавливает предыдущий journal, копирует/проверяет archive по size/SHA,
санитизирует media в private CatalogUpdates/<job>/media. После BEGIN IMMEDIATE
делает SQLite backup, слияние, планирует только отсутствующие media по canonical
id. Не заменяет существующий файл любого разрешённого расширения. Полный
pending.json fsync/atomic replace записывается ДО создания target hardlinks.
Metadata/baseline и catalog_version/catalog_updated_at/catalog_install_job_id
коммитятся вместе только после размещения всех media. Повтор/старая версия
отклоняются. Backup сохраняется локально и не входит в update/release archives.

recover_catalog_install использует bounded validated pending.json и общий
lease, не PID или наличие marker-файла. SQLite commit job id — источник истины.
До commit: SQLite откатила transaction; удалить только target, который всё ещё
является hardlink собственного stage и совпадает с записанным hash. Поздние
личные изменения не заменять backup-ом и не удалять изменённые target files.
После commit: сохранить media, при потере link восстановить из проверенного
stage, затем убрать staging/journal. Все пути проверяются на links/junctions;
backup не удалять. Повреждённый journal не исполнять, оставить для восстановления.
Checkpoint hook доступен только внутренним тестам, не API. Recovery должен
подключаться до UI; на ошибке recovery локальный вечер остаётся доступным,
но дальнейшие installs должны быть заблокированы с безопасной инструкцией.

Изображения: Pillow 12.3.0, только JPEG/PNG/WebP и совпадающее расширение;
один кадр, до 16 МиБ вход/выход, до 16 млн пикселей и 8192 по каждой стороне.
sanitize_catalog_image проверяет структуру и полностью декодирует пиксели,
применяет EXIF orientation и пересоздаёт RGB/RGBA без унаследованных info/EXIF/
ICC/XMP/comments. Producer считает SHA/size и пишет только очищенные байты;
source files не изменяет. Reader полностью декодирует каждый media entry,
ограничивая чтение до лимита одного изображения. Перед установкой consumer
также должен использовать sanitizer. Это не лицензия на распространение медиа.
Стандартная библиотека не декодирует JPEG/WebP; decoder dependency необходим.
Portable bundling JPEG/PNG/WebP plugins и isolated EXE smoke обязательны.

Тесты producer/consumer, негативные архивы, совместимость, повторная установка,
конфликты id/tmdb_id, личные данные, сбои всех фаз и backup/recovery. Полный
pytest, node --check frontend/app.js и git diff --check после каждого среза;
браузерная проверка успеха/ошибки/телефона и изолированная Windows portable
установка. Только после проверки синхронизация; .env/.venv/data не заменять.
Публикация требует отдельного подтверждения. Серверы проверки останавливать.

Запуск Windows portable: launcher вызывает recovery ДО initialize/bootstrap/
seed, поскольку эти операции выполняются до ASGI lifespan. Повторный recovery
в lifespan идемпотентен. recovery_error не мешает обычному запуску; catalog
install остаётся заблокирован. База вне папки Tonight не поддерживается для
catalog install (обычный вечер продолжает работать).

Публикация: stable tag catalog-vX.Y.Z, точное имя Tonight-catalog-X.Y.Z.zip,
размер и digest SHA-256 в GitHub API. При создании и публикации черновика
обязательно make_latest="false"; /releases/latest сохраняется за vX.Y.Z
приложения для совместимости с уже опубликованным updater 1.6.5.

Ошибки совместимости: reader возвращает typed CatalogCompatibilityError с
канонической min_app_version, downloader сохраняет только эту версию в typed
CatalogCompatibilityUpdateError. Manager формирует собственный фиксированный
совет обновить приложение и сбрасывает несовместимый offer, не выдавая success.
Size/SHA failure имеет typed CatalogIntegrityUpdateError и фиксированный совет
повторить загрузку. Raw exception text/path/token никогда не пересылается в UI.
Status/API fields и phase=error совместимы с прежним frontend контрактом.
