# Участие в разработке Tonight

Спасибо за интерес к Tonight. Приложение развивается открыто по лицензии
Apache-2.0; личные данные и секреты каждого пользователя остаются только на
его компьютере. Название и бренд регулируются [отдельными правилами](TRADEMARKS.md).

## Начало работы

1. Создайте ветку от `main` с понятным названием, например
   `feature/weekly-picks` или `fix/reconnect-counter`.
2. Создайте локальное окружение и установите зависимости:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

3. Вносите одно логически цельное изменение за раз.

Отправляя вклад для включения в проект, вы соглашаетесь лицензировать его на
условиях Apache-2.0, если заранее письменно не договорились об ином.

## Проверки перед коммитом

Для заметного изменения поведения добавьте или обновите тест. Затем запустите:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --check frontend/app.js
```

Если изменение затрагивает экран или пользовательский сценарий, проведите
локальную браузерную smoke-проверку. Не оставляйте сервер запущенным после неё.

## Что нельзя коммитить

Никогда не добавляйте в Git:

- `.env`, TMDB-токены, ключи и другие секреты;
- локальные базы данных (`data/tonight.db` и другие SQLite-файлы), историю,
  оценки, профили, резервные копии и экспорты;
- `data/posters/` и `data/backdrops/`, полученные из внешних источников;
- `.venv/`, `outputs/`, `work/`, `.exe`, `.zip` и другие готовые сборки.

Перед `git commit` проверьте `git status --short` и `git diff --cached`.
Файл `.env.example` предназначен для примеров и не должен содержать настоящий
токен.

## Документация и roadmap

Если меняется пользовательское поведение, одновременно обновите:

- подходящую feature specification, если она есть;
- `PRODUCT_ROADMAP.md` — когда этап выполнен или его контракт изменился;
- `README.md` и `PRIVACY.md`, если меняются запуск, данные, сеть или приватность;
- `CHANGELOG.md` — когда изменение попадёт в релиз.

## Релизы

Исходники и готовые Windows-сборки живут раздельно. Для пользователей готовьте
GitHub Release, а не коммит с бинарными файлами. В публичный релиз нельзя
включать `.env`, архивы `*-TMDB.zip` и личные данные. Полные данные TMDB и
изображения требуют отдельной проверки условий распространения перед публичной
или коммерческой раздачей.
