# Настройка открытого GitHub-репозитория Tonight

Этот файл — служебная памятка по настройке репозитория исходного кода Tonight.
Код выпускается по Apache-2.0, а название и бренд описаны в `TRADEMARKS.md`.

## Карточка репозитория

| Поле | Значение |
| --- | --- |
| Название | `tonight` |
| Описание | `Локальный помощник выбора фильма одному или вместе. Tonight IQ, персональные рекомендации и Tonight Mode.` |
| Видимость | `Public` после проверки состава Releases |
| Основная ветка | `main` |
| Темы | `movies`, `recommendations`, `fastapi`, `sqlite`, `local-first`, `privacy`, `windows`, `ollama` |

Не добавляйте в настройки или описание настоящий TMDB-токен. При публикации
полной переносимой сборки отдельно проверяйте отсутствие личных данных и
указывайте, что права на внешние медиа не передаются вместе с лицензией кода.

## Шаблон публичного полного релиза

**Заголовок:** `Tonight 1.7.1`

**Текст релиза:**

```markdown
Tonight 1.7.1 — локальный помощник выбора фильма одному или вместе.

Что входит в переносимую сборку:
- `Tonight.exe` для Windows;
- 671 запись каталога, локальные постеры и фоны;
- Tonight IQ, персональные рекомендации и Tonight Mode;
- выбор года кнопками и одиночный вечер без второго зрителя;
- ссылки на трейлеры;
- работа без Python и TMDB-токена.

Архив проверен на отсутствие `.env`, токенов, пользовательской истории,
оценок, сессий и резервных копий. Материалы TMDB и других правообладателей не
лицензируются Apache-2.0 вместе с кодом Tonight.

This product uses the TMDB API but is not endorsed or certified by TMDB.
```

**Вложения публичного релиза:**

- архивы исходного кода, которые GitHub создаёт автоматически;
- `Tonight-portable-1.7.1.zip` — полная Windows-сборка;
- `Tonight-update-1.7.1.zip` — пакет обновления установленной копии;
- `SHA256SUMS.txt` — контрольные суммы архивов.

Открытый код Tonight не даёт права на повторное распространение данных,
постеров, фонов или трейлеров третьих сторон. Не заявляйте в релизе, что
Apache-2.0 лицензирует такие материалы.

**Никогда не прикладывайте:**

- `.env`, ключи, токены или резервные копии;
- пользовательские базы, историю, оценки и профили;
- архивы, созданные из пользовательской копии `outputs/`.

## Публикация после локальной проверки

Для версии с автообновлением прикладывайте оба проверенных архива:
`Tonight-portable-X.Y.Z.zip` для первой установки и `Tonight-update-X.Y.Z.zip`
для обновления. С 1.7.1 update ZIP содержит только файлы программы и документацию;
каталог и изображения должны оставаться только в полном portable ZIP и
отдельных пакетах каталога. Тег — строго `vX.Y.Z`; релиз — стабильный, не Draft/Prerelease.
После загрузки проверьте в GitHub API точные имя, размер и `digest: sha256:...`
update asset. Без контрольной суммы приложение не разрешает загрузку обновления.
Для 1.7.1 опубликованы оба архива. Актуальную версию сверяйте со страницей
Releases и app/latest.json, а не по наличию локальной сборки.

1. Создайте **приватный** пустой репозиторий с указанными настройками.
2. Добавьте удалённый адрес только после проверки владельца и URL.
3. Отправьте ветку `main`.
4. Создайте тег и черновик Release.
5. До публикации ещё раз проверьте все прикреплённые файлы на отсутствие
   `.env`, токенов и личных данных.

## Отдельный релиз каталога (после проверки новой версии приложения)

Каталог публикуется отдельно от приложения. Пользователю не нужен TMDB-токен:
Tonight скачивает проверенный пакет из этого репозитория. Не прикладывайте
личную SQLite-базу. Инструмент извлекает только разрешённые поля карточек,
проверяет состав и очищает метаданные изображений.

Пример подготовки из локальной папки `data` (новый выходной файл):

```powershell
.\.venv\Scripts\python.exe scripts/build_catalog_package.py --source-data outputs/Tonight-MVP-evening-tools/data --output work/Tonight-catalog-1.0.0.zip --version 1.0.0 --min-app-version 1.6.6 --created-at 2026-10-10T00:00:00Z
```

По умолчанию пакет содержит карточки без медиа. Добавлять
`--include-media --media-rights-reviewed` можно только после отдельной проверки
прав на распространяемые изображения. Флаг фиксирует решение автора, но не
предоставляет права и не заменяет разрешение правообладателя. Лицензия кода не
лицензирует постеры и другие внешние материалы. Пакет не содержит сами фильмы
или видео трейлеров: только карточки, разрешённые картинки и ссылки.

Порядок публикации после отдельного подтверждения:

1. Проверить установку этого пакета в изолированной Windows portable-копии,
   сохранность истории, оценок, настроек и работу без токена.
2. Создать стабильный релиз с тегом строго `catalog-v1.0.0` и одним вложением
   `Tonight-catalog-1.0.0.zip`. Версия каталога независима от версии приложения;
   `min_app_version` должна указывать первую проверенную совместимую версию.
3. **Не отмечать релиз каталога как Latest.** При создании и при публикации
   черновика через GitHub API явно передавать `"make_latest": "false"`
   (строка, не JSON boolean). В веб-форме отключить «Set as the latest release».
   Уже опубликованная 1.6.5 ищет приложение через `/releases/latest`: релиз
   каталога не должен скрыть от неё обновление самого приложения.
4. После публикации проверить публичный API: точные имя, размер и
   `digest: sha256:...` вложения; `draft=false`, `prerelease=false`. Без размера
   и SHA-256 Tonight не разрешает скачивание. `/releases/latest` должен по-прежнему
   возвращать релиз приложения с тегом `vX.Y.Z`, не `catalog-vX.Y.Z`.
5. Проверить обнаружение и загрузку из Tonight без TMDB-токена. Не объявлять
   пакет доступным пользователям до этой проверки.

Семантика Latest: [официальная документация GitHub Releases API](https://docs.github.com/en/rest/releases/releases#create-a-release).
Команда подготовки сама ничего не публикует. Каталожные примеры выше описывают
отдельный процесс и не меняют актуальную версию приложения 1.7.1.

## Манифест обновления приложения

Начиная с 1.6.9 проверка сначала читает app/latest.json из main через raw.githubusercontent.com. GitHub Releases API используется только при HTTP 404. Манифест содержит format_version=1, app_version, archive_url, size_bytes и sha256; не добавляйте секреты или пользовательские данные.

После публикации релиза проверьте размер и digest обоих assets. Подготовьте описание командой python -m scripts.build_app_manifest --archive <Tonight-update-X.Y.Z.zip> --output <новый-файл.json>. Сравните SHA-256 с опубликованным asset и только затем замените app/latest.json проверенным файлом и отправьте main. Не указывайте ещё не опубликованный архив: приложение доверяет этому описанию при обнаружении, а перед установкой повторно проверяет файл и его версию.
