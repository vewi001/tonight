# Настройка открытого GitHub-репозитория Tonight

Этот файл — служебная памятка по настройке репозитория исходного кода Tonight.
Код выпускается по Apache-2.0, а название и бренд описаны в `TRADEMARKS.md`.

## Карточка репозитория

| Поле | Значение |
| --- | --- |
| Название | `tonight` |
| Описание | `Локальное приложение для спокойного совместного выбора фильма.` |
| Видимость | `Public` после проверки состава Releases |
| Основная ветка | `main` |
| Темы | `movies`, `recommendations`, `fastapi`, `sqlite`, `local-first`, `privacy`, `windows`, `ollama` |

Не добавляйте в настройки или описание настоящий TMDB-токен. До отдельного
лицензионного решения не прикладывайте к публичным Releases полный
TMDB-каталог и изображения.

## Шаблон публичного source-only релиза

**Заголовок:** `Tonight 1.6.4`

**Текст релиза:**

```markdown
Tonight 1.6.4 — первый открытый выпуск исходного кода Tonight.

Что входит:
- исходный код приложения;
- Apache License 2.0;
- правила использования названия и бренда Tonight;
- указания по материалам третьих сторон и TMDB.

Этот выпуск намеренно содержит только автоматически созданные GitHub архивы
исходного кода. Готовые пакеты с данными и изображениями третьих сторон не
приложены.

This product uses the TMDB API but is not endorsed or certified by TMDB.
```

**Вложения публичного релиза:**

- архивы исходного кода, которые GitHub создаёт автоматически;

Переносимые ZIP-пакеты можно публиковать только после отдельной проверки прав на
все включённые данные и изображения.

Открытый код Tonight не даёт права на повторное распространение данных,
постеров, фонов или трейлеров третьих сторон. Пока такая проверка не завершена,
публичный Release должен содержать только исходный код.

**Никогда не прикладывайте:**

- архивы с именем `*-TMDB.zip`;
- `.env`, ключи, токены или резервные копии;
- пользовательские базы, историю, оценки и профили;
- архивы, созданные из пользовательской копии `outputs/`.

## Публикация после локальной проверки

1. Создайте **приватный** пустой репозиторий с указанными настройками.
2. Добавьте удалённый адрес только после проверки владельца и URL.
3. Отправьте ветку `main`.
4. Создайте тег и черновик Release.
5. До публикации ещё раз проверьте все прикреплённые файлы на отсутствие
   `.env`, токенов и личных данных.
