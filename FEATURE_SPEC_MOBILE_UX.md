# Мобильный интерфейс Tonight

## Проверенные проблемы (11 октября 2026)

- В браузерной эмуляции на 360, 390 и 430 px названия разделов скрыты: две одинаковые кнопки-сердца неразличимы без угадывания.
- На 360×780 карточка заканчивается на 832 px. На 844×390 реакции начинаются на 883 px: постер вытесняет действия далеко вниз.
- Ввод в фильтр «На потом» полностью перерисовывает страницу после каждого символа и теряет фокус. Черновики и фокус также требуют проверки при WebSocket-перерисовке.
- Небольшие кнопки профиля не имеют гарантированной области 44×44; отсутствуют отступы safe-area.

## Контракт

1. На телефоне верхняя панель содержит бренд и подписанную кнопку «Разделы». Раскрываемая навигация сохраняет текстовые названия всех доступных разделов. Компьютер сохраняет обычную навигацию. Доступ к каталогу и обновлению с телефона не расширяется.
2. Основные области нажатия не меньше 44×44 CSS px. Системный шрифт, основной текст 16 px, второстепенный читаемый. Видимый фокус у кнопок, ссылок и полей.
3. Мобильная карточка использует ограниченную высоту постера; название, год, длительность и подписанные реакции остаются доступны. Краткое описание раскрывается кнопкой «Раскрыть целиком» под постером, вне обрезаемой области. Полный текст переносится и прокручивается вместе со страницей; его можно свернуть. Чтение/выделение текста и клавиши внутри раскрытия не отправляют реакцию. Повторная отрисовка того же фильма сохраняет раскрытие. В горизонтальной ориентации реакции остаются рядом с постером, полное описание занимает отдельную строку. Прокрутка допустима, обрезание содержимого — нет.
4. Поворот экрана и обновления соединения не сбрасывают шаг, ограничения и незавершённый ввод. Фильтр списка не закрывает клавиатуру после каждого символа.
5. Учитываются safe-area, динамическая высота окна, увеличение текста. Нет горизонтальной прокрутки всей страницы или перекрытия действий уведомлениями.
6. Не меняются рекомендации, стоп-жанры, права телефона, формат пользовательских данных и безопасность обновления. Нет новых внешних шрифтов и зависимостей.

## Приёмка

Полный путь: приглашение/QR → код → зритель → настроение → ограничения → реакции → ожидание → рекомендации → подтверждение. Эмуляция 360/390/430 px и горизонтальная ориентация, проверка десктопа, снимки до/после; отдельные проверки ввода, фокуса и переподключения. Эмуляция не является испытанием физического телефона.

После каждого среза: новые регрессионные тесты, полный pytest, node --check frontend/app.js, git diff --check. Затем синхронизация пользовательской копии с сохранением .env, .venv и data. Публикация только после проверки полной сборки и обновления предыдущей версии.
