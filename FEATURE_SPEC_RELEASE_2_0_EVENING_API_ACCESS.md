# Tonight 2.0 — доступ телефона к данным текущего вечера

## Риск

Код приглашения защищает вход и WebSocket, но этого недостаточно, если обычные
HTTP-запросы с другого устройства могут прочитать состояние вечера без кода.

## Контракт

- До ввода кода LAN-клиент получает только минимальные сведения, необходимые
  для экрана входа: идентификатор, дату и нейтральное название вечера.
- Полное состояние вечера, история, оценки, профиль вкуса, недельная подборка,
  франшизы и список «На потом» требуют заголовок `X-Tonight-Code`.
- Запросы изменения предпочтений, реакций, выбора, оценок и профиля требуют тот
  же заголовок.
- `join` продолжает принимать код в теле запроса; после успешного входа frontend
  автоматически добавляет код ко всем последующим API-запросам телефона.
- Браузер на `localhost` работает без кода.
- Публичными остаются health/setup/diagnostics, QR, поиск и медиа каталога.
- Неверный или устаревший код возвращает `403` и переводит телефон на понятный
  экран повторного ввода.

## Проверка

1. LAN-клиент без кода не получает участников, предпочтения и рекомендации из
   `/api/sessions/active` или `/api/invite`.
2. Представительные личные GET и POST запросы без заголовка получают `403`.
3. Те же запросы с текущим кодом проходят.
4. Автоматические тесты проверяют, что frontend добавляет заголовок только на
   втором устройстве.
5. Браузерная smoke-проверка проходит полный вход телефона и открывает историю
   и профиль вкуса; запрос без заголовка отдельно получает `403`.
