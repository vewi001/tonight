# Ход реализации автообновления

09.10.2026 — цель активна. Backend, UI и отдельный обновитель проверены, включая
полный путь браузерной кнопки на Windows EXE. Версия 1.6.5 опубликована
по явному запросу владельца и проверена как публичный Latest.

## Проверено

- Два read-only исследования на gpt-6-luna/low завершены. Код меняет только основной агент.
- Контракт: `FEATURE_SPEC_AUTO_UPDATE.md`.
- `backend/auto_update.py`: стабильные числовые версии, строгий выбор update ZIP,
  обязательный размер/SHA-256 GitHub asset, публичный запрос без auth/token/cookie,
  ограниченные HTTPS-редиректы, потоковая загрузка, проверка ZIP/манифеста,
  отсутствие готового файла после неудачной загрузки.
- `backend/release.py`: Windows-пути и приватные имена защищены без учёта регистра;
  распаковка до backup/замены; атомарная замена каждого файла через временный
  соседний файл; возврат заменённых файлов после ошибки установки.
- `Updates/` сохраняется и не копируется в снимок программы.
- Менеджер состояния: кэш фоновых проверок 6 часов, ручная проверка, одна загрузка,
  прогресс, повтор после ошибки. API `/api/updates`, `/api/updates/check`,
  `/api/updates/install`: localhost-only, заголовок действия и проверка Origin/Host.
- Фоновая проверка в lifespan. Отдельный updater копируется в Updates/runner,
  ждёт завершения PID процесса и onefile bootloader, перепроверяет пакет,
  устанавливает, перезапускает. Запуск новой версии с OSError откатывает файлы.
- Desktop ждёт остановки worker до закрытия. Проверка существования PID на
  Windows использует read-only OpenProcess/WaitForSingleObject, а не os.kill.
- UI: уведомление, версия/размер, «Скачать и обновить», «Не сейчас», ручная проверка
  на экране диагностики, проценты загрузки, ожидание перезапуска. На телефоне скрыто.
  Polling меняет только панель обновлений, не сбрасывая текущее действие/форму.
- Browser smoke на 127.0.0.1:8767: новый релиз, откладывание, ручная проверка,
  безопасная ошибка загрузки и повтор. Сервер остановлен. Использовался фиктивный
  релиз в тестовой базе work/update-ui-smoke.db, без реального скачивания/публикации.
- Обновитель больше не импортирует launcher/backend.main: running marker вынесен
  в лёгкий backend/process_state.py. Это устраняет зависимость updater EXE от frontend.
- Двустороннее подтверждение handoff: helper проверяет пакет и пишет ready;
  родитель проверяет живой процесс, разрешает продолжение и только затем закрывается.
  Ошибка запуска/таймаут оставляет Tonight работающим; запоздалый helper видит abort.
- Ручной updater EXE тоже запускает копию из Updates/runner и ждёт завершения
  исходного EXE/bootloader. Поэтому будущие пакеты могут заменять сам обновитель.
- Builder теперь включает «Обновить Tonight.exe» в update ZIP; состав пакета
  проверен отдельным тестом и не включает пользовательские .env/data.
- Ошибка манифеста при handoff переводит интерфейс в error и не закрывает Tonight.
  Ошибка повторной проверки/установки после остановки снова запускает прежнюю
  программу. Три регрессионных сценария сначала воспроизведены, затем исправлены.
- 187 тестов проходят (18.20 с); node --check frontend/app.js и git diff --check проходят.
- Код и локальная сборка имеют версию 1.6.5; релиз не опубликован.
  README/PRIVACY/GITHUB_SETUP описывают GitHub-проверку, digest и переход с 1.6.4.
- Browser отслеживает исходную версию сразу после команды установки, чтобы
  быстрый перезапуск между двумя polling-запросами всё равно обновил страницу.
  Регрессионный UI-тест прошёл; полный pytest после этого — 187 (16.09 с).
- Собраны `work/auto-update-1.6.5/Tonight-portable-1.6.5/` и оба ZIP.
- `scripts/smoke_portable_update.py` действительно запустил старый EXE 1.6.4,
  получил подтверждение нового helper EXE, завершил только изолированные процессы,
  заменил main/updater и дождался API новой версии 1.6.5.
  Сохранены .env, .venv, тестовая watch_history/feedback и пользовательское медиа;
  создан before-update backup и снимок прежнего EXE. В finally приложение остановлено.
  Фикстура: work/auto-update-1.6.5/exe-smoke-coj6c0hd. Порты 8000/8767/8771 закрыты.
- Независимый короткий read-only обзор `update_final_review` завершён (Luna/low).
  Подтверждён риск ошибки во время восстановления файлов и нетранзакционного
  manual rollback. Рекомендации про WAIT_FAILED и включение Updates в snapshot
  не подтверждены текущим кодом: WAIT_FAILED считается живым, Updates исключён.
  Накопление runner-копий — ограниченный локальный недостаток, не утечка данных.
- Срез восстановления: atomic copy используется и при возврате файлов; manual
  rollback сохраняет текущие файлы до завершения всей операции и возвращает их
  при обычном сбое. Двойной сбой сообщает RecoveryError, сохраняет recovery snapshot
  и не запускает потенциально неполную программу. Манифест тоже заменяется атомарно.
- Воспроизведена и закрыта запись через настоящую Windows junction catalog -> data.
  Проверяются все родители целевых файлов и служебного rollback, symlink/reparse
  запрещены до backup/замены. Защита snapshot не следует по junction.
- Подтверждение proceed публикуется атомарно, helper принимает только полный текст.
  Пустое/частичное подтверждение не разрешает установку.
- После этого среза 192 теста проходят (16.69 с), node/diff check проходят.
  Осталось 54% текущего окна. Новые backend/updater/tests синхронизированы отдельно.
  ZIP/EXE предыдущего smoke пока НЕ содержат последние усиления: нужна пересборка.
- Начальный остаток новой цели: 65% окна 300 минут, 36% недельного лимита.
- После двух срезов осталось 62% окна; сброс 09.10.2026 23:49:01 МСК.
- PyInstaller 6.22.3 установлен. Правило запуска независимого процесса с
  PYINSTALLER_RESET_ENVIRONMENT проверено по официальной документации:
  https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#using-sys-executable-to-spawn-subprocesses
